# 추천 품질 개선과 실제 Gemini 검증

2026-11-14. 최신 시연 구역 기준은 [구역 문서](yongin-demo-areas.md)를 따른다.

## 변경한 추천 방식

- 저장된 category_preference와 excluded_products에서 꽃/화분·디저트·음료·도서 등 알려진 상품 종류를 해석한다. 14개 어휘군을 사용하는 규칙 기반 후보 검색이며, 별도 학습 모델이나 완전한 한국어 문장 이해 기능은 아니다. 원문 답변은 Gemini에도 전달한다.
- 두 종류 이상을 함께 지정하면 두 상품이 지정 종류를 모두 포함해야 한다. '또는/혹은/아무거나/중 하나'는 대안으로 처리한다. 지원하는 부정 표현과 제외 종류를 먼저 반영한다. 예산 안에 조합이 없으면 READY와 빈 목록이며 AI를 호출하지 않는다.
- 현재 시연 데이터의 음료 최저가는 9,000원, 디저트 최저가는 16,000원이다. 따라서 음료+디저트를 20,000원에 구성할 수 없다. 상품 가격은 변경하지 않았다.
- 구역별 256개, 업종 조합별 최대 12개에 더해 상품별 상위 4개를 유지해 낮은 ID의 인기 상품 하나에 후보가 몰리지 않도록 한다.
- AI 입력 최대 12개를 고를 때 상품·점포는 최대 3회, 정규화한 상품명 조합은 최대 2회다. 선호 충족도, 반복 감점, 다른 구역·업종을 고려한다. 기존 scoreFirstCount 인자는 생성자 호환성을 위해 남아 있으나 모든 선택 슬롯에 다양성을 적용한다.
- Gemini 평가와 기존 demo 학습 가중치로 최종 최대 6개를 고른다. 상품·점포·동일 상품명 조합은 각각 최대 2회다. 가능한 후보가 적으면 6개를 억지로 채우지 않는다. 학습 가중치와 프롬프트·특징 계약은 바꾸지 않았다.

## 받는 사람 우선순위 (2026-11-15)

- 받는 사람이 입력되면 최종 순위는 받는 사람 적합도를 먼저 비교하고, 같은 적합도 안에서 기존 모델 총점과 다양성 감점을 적용한다. baseline/trained/demo 가중치로 이 순서가 뒤집히지 않는다.
- 부모님(엄마·아빠·어머니·아버지 포함)은 상품명 기준으로 꽃+케이크, 꽃/케이크 두 상품, 꽃/케이크 한 상품, 기타 조합 순으로 후보 검색부터 최종 순위까지 우선한다. 꽃무늬 문구나 케이크 토퍼 등은 우선 상품으로 취급하지 않는다.
- 부모님 선택에서는 category_preference의 여러 종류를 모두 포함해야 한다는 필터를 적용하지 않고 선호 점수로 반영한다. 명시적인 excluded_products, 예산, 구역/거리, 서로 다른 점포, 판매/픽업 가능 조건과 반복 노출 상한은 유지한다.
- 부모님 외 대상은 최종 AI recipient_score를 우선한다. 별도 상품 종류 규칙은 적용하지 않는다. 받는 사람 미입력 시 기존 순서를 유지한다.
- 기존에 저장된 추천 순위는 바꾸지 않으며 새 구매요청부터 적용된다. 모델 특징·가중치 파일과 프롬프트 계약은 유지한다.

## 생일·생신 홀케이크 필수 구성 (2026-11-15)

- 생일·생신·생일파티는 각 조합에 홀케이크를 정확히 한 개 포함한다. 이름/설명에서 홀케이크 또는 케이크 호수가 확인되어야 하며, 조각·미니·도시락·컵·팬·롤 케이크와 장식용 토퍼·상자는 홀케이크로 취급하지 않는다. 일반적인 '케이크' 이름만으로 홀케이크라고 추정하지 않는다.
- 후보 생성과 AI 평가 직전에 동일한 필수 구성 검사를 적용한다. 예약 가능한 홀케이크가 없거나, 제외 상품 또는 예산 조건 때문에 구성할 수 없으면 빈 추천 목록을 반환한다. 케이크 없는 문구 조합으로 대체하지 않는다.
- 할머니·할아버지·조부모도 가족 선물 우선순위에 포함한다. 생일·생신은 받는 사람 적합도가 같은 후보 안에서 예산 활용도(총액/예산), 기존 모델 점수 순으로 비교한다. 후보 보관 단계에서도 이 기준을 적용해 저가 조합이 비싼 홀케이크+꽃 조합을 밀어내지 않게 한다. 예산은 계속 상한이며 적합도를 낮추면서 예산을 채우지는 않는다.
- 생일·생신의 category_preference는 선호 점수로 적용하며 홀케이크 필수 구성을 막는 복수 종류 필터로 사용하지 않는다. 명시적 제외 상품과 판매·픽업·거리·점포 조건은 유지한다. 다른 구매 목적의 예산 정렬과 모델 특징/프롬프트 계약은 유지한다.
- 시연 카탈로그에 홀케이크 1호/2호/3호(35,000/55,000/65,000원) 72개와 생신 꽃다발/대형 꽃바구니(45,000/65,000원) 6개를 추가했다. 모두 가상 상품으로 실제 점포 메뉴가 아니다. 기존 상품의 가격·상태는 변경하지 않는다.
- '뜨개질을 좋아하시는 할머니'처럼 받는 사람/취향/선호 종류 답변에 뜨개질 의도가 있으면 일반적인 가족 선물 규칙보다 구체적인 취미를 우선한다. 이 경우 뜨개실·털실·코바늘·대바늘 등 재료를 필수로 포함하며, 생일에는 **뜨개질 재료 + 홀케이크**만 후보로 만든다. 재료가 없거나 제외된 경우 커피·문구·꽃으로 대신 채우지 않는다. 완제품 가방·인형·교재는 재료로 취급하지 않는다. 뜨개질 부정 표현도 기존 선호 파서로 처리한다.
- 보정 구역의 시연 공예 점포에 뜨개질 재료 상품 3종(25,000/45,000/65,000원)을 추가했다. '뜨개질 좋아하시는 할머니 / 생일 / 뜨개질 재료와 홀케이크 / 예산 120,000원'의 카탈로그 검증에서는 재료 세트 65,000원 + 홀케이크 2호 55,000원 조합이 우선된다. 총 시연 상품은 1,980개다.
- `BirthdayRecommendationTest`는 필수 구성, 부적합 케이크 제외, 홀케이크 품절/예산 부족/명시적 제외 시 빈 결과, 저가 선호 모델에 대한 회귀를 검사한다. `CsvDemoBirthdayRecommendationTest`는 패키지 카탈로그 전체로 할머니 생일 6만·9만·12만 원을 비교한다. AI 평가는 테스트 대역이며 실제 Gemini 응답 검증은 아니다.

## 중복 점포

정규화한 상호와 도로명 건물 주소가 같으면 추천 관점에서 같은 점포로 취급한다. '[시연]' 접두어, 공백·구두점, 경기/경기도 표기를 정규화한다. 같은 상호가 같은 건물에서 층·호만 다른 경우도 보수적으로 같은 점포로 취급한다. 같은 쇼핑몰의 다른 상호, 같은 상호의 다른 건물은 구분한다.

원본 공공데이터와 Store 행은 병합·삭제하지 않는다. 추천 생성·저장 직전·기존 목록·상세·대체 후보 재검증에서 같은 식별 기준을 사용한다. 기존 잘못된 추천은 DUPLICATE_STORE_IDENTITY 사유로 UNAVAILABLE이 된다. BE1 예약 로직 자체는 변경하지 않았다. 내부 store_identity는 Gemini JSON과 공개 HTTP 응답에 노출하지 않는다.

응답 usageMetadata에서 입력·출력·추론·전체·캐시·도구 입력 토큰 중 제공된 숫자만 GEMINI_USAGE JSON 로그에 기록한다. 원문 프롬프트·API 키·응답 내용은 로그에 기록하지 않는다. 이번 응답에는 thoughtsTokenCount가 없었고 전체 토큰은 입력+출력과 같았다. 메타데이터가 없으면 사용량을 0으로 추정하지 않는다.

recommendation.ai.max-attempts는 1 또는 2이며 기본값은 2다. 이번 실검증에서는 1로 설정해 자동 재시도를 끄고 실제 평가를 2건으로 제한했다. 일반 실행에서도 자동 재시도를 끄려면 --recommendation.ai.max-attempts=1을 전달한다. 계정 전체 예산 차단 기능을 구현한 것은 아니다.
