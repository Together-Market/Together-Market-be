# 추천 품질 개선과 실제 Gemini 검증

2026-11-14. 최신 시연 구역 기준은 [구역 문서](yongin-demo-areas.md)를 따른다.

## 변경한 추천 방식

- 저장된 category_preference와 excluded_products에서 꽃/화분·디저트·음료·도서 등 알려진 상품 종류를 해석한다. 14개 어휘군을 사용하는 규칙 기반 후보 검색이며, 별도 학습 모델이나 완전한 한국어 문장 이해 기능은 아니다. 원문 답변은 Gemini에도 전달한다.
- 두 종류 이상을 함께 지정하면 두 상품이 지정 종류를 모두 포함해야 한다. '또는/혹은/아무거나/중 하나'는 대안으로 처리한다. 지원하는 부정 표현과 제외 종류를 먼저 반영한다. 예산 안에 조합이 없으면 READY와 빈 목록이며 AI를 호출하지 않는다.
- 현재 시연 데이터의 음료 최저가는 9,000원, 디저트 최저가는 16,000원이다. 따라서 음료+디저트를 20,000원에 구성할 수 없다. 상품 가격은 변경하지 않았다.
- 구역별 256개, 업종 조합별 최대 12개에 더해 상품별 상위 4개를 유지해 낮은 ID의 인기 상품 하나에 후보가 몰리지 않도록 한다.
- AI 입력 최대 12개를 고를 때 상품·점포는 최대 3회, 정규화한 상품명 조합은 최대 2회다. 선호 충족도, 반복 감점, 다른 구역·업종을 고려한다. 기존 scoreFirstCount 인자는 생성자 호환성을 위해 남아 있으나 모든 선택 슬롯에 다양성을 적용한다.
- Gemini 평가와 기존 demo 학습 가중치로 최종 최대 6개를 고른다. 상품·점포·동일 상품명 조합은 각각 최대 2회다. 가능한 후보가 적으면 6개를 억지로 채우지 않는다. 학습 가중치와 프롬프트·특징 계약은 바꾸지 않았다.

## 중복 점포

정규화한 상호와 도로명 건물 주소가 같으면 추천 관점에서 같은 점포로 취급한다. '[시연]' 접두어, 공백·구두점, 경기/경기도 표기를 정규화한다. 같은 상호가 같은 건물에서 층·호만 다른 경우도 보수적으로 같은 점포로 취급한다. 같은 쇼핑몰의 다른 상호, 같은 상호의 다른 건물은 구분한다.

원본 공공데이터와 Store 행은 병합·삭제하지 않는다. 추천 생성·저장 직전·기존 목록·상세·대체 후보 재검증에서 같은 식별 기준을 사용한다. 기존 잘못된 추천은 DUPLICATE_STORE_IDENTITY 사유로 UNAVAILABLE이 된다. BE1 예약 로직 자체는 변경하지 않았다. 내부 store_identity는 Gemini JSON과 공개 HTTP 응답에 노출하지 않는다.

환율을 계산 가정으로만 1달러=1,500원으로 두면 두 요청 합계 약 9.83원, 부가세 10% 단순 가산 시 약 10.81원이다. 비슷한 요청 100회는 이번 두 사례 기준 약 400~600원(세금 전)이지만 요청 길이·출력·재시도에 따라 달라진다. 계정의 실제 잔액이나 지출 차단 설정을 조회한 결과는 아니다.

응답 usageMetadata에서 입력·출력·추론·전체·캐시·도구 입력 토큰 중 제공된 숫자만 GEMINI_USAGE JSON 로그에 기록한다. 원문 프롬프트·API 키·응답 내용은 로그에 기록하지 않는다. 이번 응답에는 thoughtsTokenCount가 없었고 전체 토큰은 입력+출력과 같았다. 메타데이터가 없으면 사용량을 0으로 추정하지 않는다.

recommendation.ai.max-attempts는 1 또는 2이며 기본값은 2다. 이번 실검증에서는 1로 설정해 자동 재시도를 끄고 실제 평가를 2건으로 제한했다. 일반 실행에서도 자동 재시도를 끄려면 --recommendation.ai.max-attempts=1을 전달한다. 계정 전체 예산 차단 기능을 구현한 것은 아니다.
