# OWN-04~05 일정 관리 (이슈 #13)

- GET /owner/stores/{store_id}/hours: 본인 점포의 주간 및 특정일 일정 전체 조회. 없으면 items=[] (200).
- PUT 같은 경로: 전체 교체 (200). items=[]는 전체 삭제. 생략한 기존 일정은 제거.
- 기존 OwnerAccess 인증 인터페이스와 점포 전용 응답/예외 처리를 재사용한다. BE1 연결 전 503 차단 및 세션/CSRF 연결 대기는 동일하다.
- ID는 문자열, JSON은 snake_case. 일정 행의 DB ID는 응답에 노출하지 않는다.
- 주간(요일 오름차순) 다음 특정일(날짜 오름차순), 같은 날짜는 BUSINESS/PICKUP 순으로 반환한다.

## 입력 검증

body에는 items 배열만 허용한다. 각 항목은 weekday,target_date,hour_type,is_closed,opens_at,closes_at,end_day_offset의 **7개** 필드가 필수이며 nullable 값은 명시적 null로 보낸다.
요일은 월요일 1~일요일 7. weekday와 target_date 중 정확히 하나만 값이 있어야 한다.
날짜는 유효한 YYYY-MM-DD(MySQL DATE 범위), 시간은 HH:mm:ss. 알 수 없는 필드/enum과 숫자 문자열·소수 요일은 거부한다.
같은 시간 구분의 동일 요일 또는 특정일은 중복 입력할 수 없다. BUSINESS와 PICKUP은 별도 일정이며, 특정일 예외와 주간 규칙은 함께 저장할 수 있다.
휴무는 시간 null, 가산일수 0. 운영은 시간 필수, 가산일수 0/1, 구간은 0초 초과 24시간 이하.
수령 일정이 영업시간 밖이면 저장은 가능하지만 기존 공통 검증에서 두 조건을 모두 확인하므로 실제 예약 가능으로 판단하지 않는다.

## 원자성과 동시 처리

전체 입력 검증 후 Service에서 OWNER/점포 소유권을 확인한다. PUT은 기존 점포 행에 비관적 잠금을 걸어 일정이 없는 경우에도 교체 요청을 직렬화한다.
삭제는 벌크 DELETE로 즉시 실행하고 새 일정은 saveAllAndFlush로 저장한다. 동일 UNIQUE 키 재등록 시 삭제/삽입 순서가 보장되며, DB 오류는 트랜잭션 전체를 롤백한다.
DB 마이그레이션 변경은 없다. 입력 오류는 400, 타인/없는 점포는 404, 역할 불일치는 403.

## 테스트

HTTP 테스트: 정상 응답 형식, null/빈 목록, 주간·특정일, 자정 넘김·24시간 경계, 중복/잘못된 입력, 소유권/역할.
조건부 MySQL 테스트: 같은 UNIQUE 키 재등록, 전체 삭제, 실제 INSERT 오류 후 기존 데이터 복원, 동시 교체 시 혼합 방지, 공통 일정 검증 연결.
통합 테스트는 별도 테스트 DB의 MYSQL_TEST_URL/USERNAME/PASSWORD 환경변수를 사용한다. 컨테이너의 격리 DB에서 실행한다.

## 실행 결과 (2026-11-13)

- spotlessCheck 및 전체 build 통과.
- 신규 HTTP 테스트 6개와 실제 MySQL 8.4 통합 테스트 3개 통과.
- INSERT 실패를 테스트용 트리거로 유발해 삭제까지 롤백되는 것을 확인. 트리거는 finally에서 제거.
- 같은 점포에 대한 동시 PUT 두 건 완료 후 일정이 섞이지 않는 것을 확인.
- 실제 세션·CSRF 연결은 BE1 OwnerAccess 구현 대기 상태다. 테스트에서는 인증만 대체한다.
