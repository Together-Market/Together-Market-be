# 배포 전 점검·보안 검토

2026-11-15, 로컬 `dev`의 `0cea432` 기반 미커밋 작업 트리. 검토 대상은 이번 주소 미리보기·좌표 저장 정책·공공데이터 보완·REC-03·CORS·최종 예약 거리 검증 변경이다. 커밋·푸시·병합과 실제 DB 작업은 사용자가 직접 한다.

## 결론과 검증 근거

로컬 구현·자동 검증은 완료했다. Java 21의 `spotlessApply spotlessCheck build --offline --no-daemon` 성공, 총 378개 중 324개 통과·54개 조건부 생략·실패/오류 0개. `git diff --check` 통과. 실제 MySQL 조건부 테스트와 배포 환경 검증은 수행하지 않았다. 조건부 테스트의 생략 개수는 JUnit 보고서 기준이며 파라미터별 실제 DB 실행 횟수를 뜻하지 않는다.

점검한 변경 코드에서 추가로 확인한 인증 우회·외부 URL 주입·임의 좌표 저장 문제는 없었다. 이 결론은 아래 범위의 정적 검토·모의 테스트에 한정한다. 운영 침투 테스트나 전체 의존성 취약점 스캔을 완료했다는 의미는 아니다.

| --- | --- |
| 최종 예약 거리 | 점포 ID 순서로 행 잠금 후 refresh, 현재 좌표의 반올림 전 거리로 500m 검증. 누락·범위 오류·거리 초과이면 저장 전에 공통 409 |

Git 검사는 파일명·ignore·알려진 설정 구조 검사다. 비밀값을 읽지 말라는 사용자 지침에 따라 실제 .env, 개인 IDE 설정, 키 파일과 전체 Git 이력의 비밀값 검색은 하지 않았다. 파일명 검사만으로 임의 이름의 파일 안에 비밀값이 전혀 없다고 보장하지 않는다. 확인한 설정 예시는 환경변수 이름과 비밀값 없는 구조만 포함한다.

## 의존성 공지 제한 검토

실행 JAR에서 확인한 버전: Spring Boot 4.1.2, Spring Security 7.1.2, Spring Framework 7.0.10, Tomcat 11.0.27, Jackson 3.1.7, MySQL Connector/J 9.7.0. 이번 작업은 의존성 버전을 변경하지 않았다.

- Spring Security의 [CVE-2026-41707](https://spring.io/security/cve-2026-41707/), [CVE-2026-47841](https://spring.io/security/cve-2026-47841/), [CVE-2026-47842](https://spring.io/security/cve-2026-47842/), [CVE-2026-47877](https://spring.io/security/cve-2026-47877/)는 공식 공지에서 7.1 계열 수정 버전을 7.1.1로 제시한다. 현재 7.1.2는 이 네 공지의 명시된 영향 버전 밖이다.
- [Tomcat 공식 보안 공지](https://tomcat.apache.org/security-11)의 CVE-2026-103119와 CVE-2026-101356은 11.0.27에서 수정되었고 영향 범위는 11.0.26까지다. 현재 실행 JAR은 11.0.27을 사용한다.
- 이 공지 대조는 전체 CVE·전이 의존성 검사를 대체하지 않는다. 전체 SCA 도구 실행과 배포 OS/JDK 패치 수준 검증은 미실시다. 배포 대상과 최종 아티팩트가 정해지면 그 버전 기준으로 확인한다.

## 배포 환경에서 결정·확인할 사항

1. **요청 횟수 제한:** 현재 로그인·주소 미리보기 HTTP API에 자체 IP/계정별 rate limiter는 없다. 배치의 호출 상한과 카카오 쿼터는 공개 HTTP 엔드포인트의 호출 제한을 대신하지 않는다. 공개 배포 시 서비스/프록시의 제한 또는 애플리케이션 제한을 적용할 위치를 정해야 한다.
2. **HTTPS와 세션:** 배포 HTTPS 서버에 Secure=true·SameSite=none과 정확한 프런트 출처를 설정한다. 현재 메모리 세션은 재시작 시 사라지므로 우선 단일 인스턴스 기준으로 운영하고, 여러 대를 쓰면 공유 세션 방식을 결정한다. 실제 브라우저 검증은 백엔드 배포 후 진행한다.
3. **DB 접근 권한·네트워크:** 배포 서비스와 DB 위치가 미정이라 실제 방화벽·DB 계정을 확인하지 않았다. 애플리케이션 DB 계정은 필요한 스키마/작업 범위로 제한하고 MySQL을 불특정 인터넷에 공개하지 않는다. Flyway 실행에 필요한 권한과 일반 실행 권한을 배포 방식에 맞춰 결정한다. 값은 사용자가 직접 설정한다.
4. **테스트 DB·CI:** 로컬 실제 DB는 사용하지 않았다. PR의 build-test-format, reservation-mysql, csv-demo-mysql, pr-validation 결과를 확인해야 한다. 특히 reservation-mysql은 좌표 변경 후 저장 거부·복구 후 재시도를 실제 MySQL에서 확인하도록 추가했다.
5. **정책상 기능 제한:** PROVIDED는 출처 자체를 서버가 증명하는 기능이 아니다. 프런트 계약을 지켜야 하며 카카오 응답의 출처 변경으로 우회하면 안 된다. 카카오 좌표 영구 저장은 계속 미제공이다.
