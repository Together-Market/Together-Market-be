# 두 점포 사이 거리 제한

2026-11-15 사용자 확정: 같은 구역에 있는 서로 다른 두 점포의 **직선거리 500m 이내**만 추천한다. 기존 명소 중심 반경 500m 조건과 별개다. 명소 반경 안이어도 두 점포 사이 거리가 500m를 넘으면 제외한다.

## 적용 위치

- 후보 생성: 반올림 전 WGS84 구면 직선거리로 검사한 다음, 통과한 조합만 Gemini 평가 후보로 선정한다. 가까운 조합에 점수를 더하던 기존 로직에 필수 상한을 추가했다.
- 결과 저장: AI 입력의 과거 거리 값을 신뢰하지 않고 현재 DB 점포 좌표를 읽어 재검증한다. 기준을 넘는 조합은 저장하지 않는다.
- 추천 목록·상세: 기존 후보도 현재 좌표로 확인한다. 500m 초과 또는 좌표 미확인 시 `UNAVAILABLE`, `unavailable_reasons`에 `STORE_DISTANCE_EXCEEDED_OR_UNKNOWN`을 반환한다. 조합 단위 사유이므로 `product_id`는 null이다.
- 대체 후보: 동일 구매요청의 다른 저장 후보 중 거리 조건을 통과한 후보만 제공한다.
- 신규 예약 생성: 점포 두 행을 잠그고 refresh한 최신 좌표에 같은 500m 정책을 적용한다. 누락·범위 오류·500m 초과는 저장 전에 409 `STORE_DISTANCE_EXCEEDED_OR_UNKNOWN`으로 거절한다. 이미 성공한 동일 키·동일 요청의 재응답은 좌표 변경 후에도 유지한다.

500m는 허용하고 500m 초과는 제외한다. 표시용 반올림 때문에 500.01m가 통과하지 않도록 판정과 표시를 구분한다. 좌표 누락·NaN·무한대·유효 범위 밖 좌표는 허용하지 않는다. REC-03의 `distance_meters`는 직선거리 정수 또는 null이며, 누락 시 HTTP 200과 `location_status=UNAVAILABLE`을 반환한다. [최신 주소·좌표 명세](kakao-geocoding-api.md)를 참고한다.

## 도보 경로와 범위

추후 실제 경로를 연동할 때의 목표는 도보 10분 이내다. 현재는 보행로·횡단보도·출입구를 계산하지 않으므로 도보 가능 여부나 소요시간을 보장하지 않고 도보 시간을 표시하지 않는다. TMAP 등 외부 경로 API 호출이나 추가 API 비용은 없다.

추천 생성·재조회와 BE1의 최종 신규 예약 생성에 같은 거리 정책을 적용한다. 예약 API를 직접 호출해도 검증하며 외부 주소 검색을 호출하지 않는다. DB 스키마 변경은 없다. 오류 응답·멱등성 계약은 [예약 API](BE1_RESERVATIONS.md)를 참고한다.

## 회귀 검증

`StorePairDistanceTest`는 499.99m/500.01m 경계, 잘못된 좌표, 같은 구역의 먼 점포, 기존 추천과 대체 후보의 좌표 변경을 검사한다. `StoreDistancePersistenceTest`는 AI 입력이 10m여도 현재 DB 점포 좌표가 기준을 넘으면 저장하지 않는지 검사한다. 실제 도보 경로·외부 Gemini 호출 검증은 포함하지 않는다.

2026-11-15 `dev`의 `2b67387` 기준 Java 21에서 `./gradlew.bat spotlessCheck build --offline --no-daemon` 성공. 전체 280개 중 233개 통과·조건부 DB 검사 47개 생략이며 실패·오류는 없다. 이번에 추가한 거리 검사 6개는 모두 통과했다. 이번 실행은 실제 MySQL·외부 API·실행 중 서버 검증을 포함하지 않는다.
